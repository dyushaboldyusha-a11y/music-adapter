# Проверка обновления 0.6.1 → 0.6.2

Проверены настоящие опубликованные Windows EXE, без замены кода приложения тестовыми обработчиками. Итог: **0 из 5 полных переходов завершились успешно**. Скачивание, SHA-256 и подготовка файла прошли во всех сценариях, но установка остановилась после завершения старого приложения.

| Сценарий | Скачивание и подготовка | Замена EXE и запуск 0.6.2 |
| --- | --- | --- |
| Обычный вид | Успешно | Не завершились |
| Компактный вид | Успешно | Не завершились |
| Масштаб 50% | Успешно | Не завершились |
| Папка с пробелами и кириллицей | Успешно | Не завершились |
| Повторная попытка после перезапуска | Успешно, кэш использован повторно | Не завершились |

Основная проверка: https://github.com/dyushaboldyusha-a11y/music-adapter/actions/runs/41194105826.

Короткая диагностика процессов: https://github.com/dyushaboldyusha-a11y/music-adapter/actions/runs/41198897961. Через пять секунд после нажатия установки старый переносимый процесс завершился с кодом 0, соединение с его интерфейсом закрыто, установщик уже отсутствует, нового приложения нет. `last-install.json` остаётся в фазе `ready` с `ok: false`.

Причина в `src/install-launcher.cjs`: на Windows PowerShell запускается с `detached: false`. libuv помещает такой дочерний процесс в объект задания Windows с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, поэтому завершение Electron останавливает установщик. `child.unref()` эту связь не снимает. Механизм описан в [исходниках libuv](https://github.com/libuv/libuv/blob/v1.x/src/win/process.c).

Прежняя проверка установщика завершала отдельный тестовый процесс из `WaitPid`, оставляя процесс Node.js, который запустил PowerShell, работающим. Поэтому она проверяла замену файлов, но пропускала завершение установщика вместе с настоящим родительским приложением.

Контрольные суммы опубликованных EXE:

- 0.6.1: `58ad68601331acb9ecf4805ab1cc4a0ded1c7ef1cf94a00416a2d348a1264aa6`.
- 0.6.2: `0ec266f5c61d9d0636841c0a65650800d0e011e74b3f496c84b6635408fdb274`.

Переход с установленной 0.6.1 требует ручного запуска 0.6.2 после полного завершения старого приложения. Изменения в новом скачанном EXE не исправляют способ запуска установщика уже работающей старой версии. В опубликованной 0.6.2 этот код запуска тоже остаётся прежним. Исправления белого оформления и стартового масштаба включены в 0.6.2 и прошли свои проверки, но это не подтверждает исправность встроенной установки.
