## Автоматические профили

В «Мой виджет» задайте название и имя EXE игры/приложения, например `game.exe`,
и сохраните текущий вид. Включите автоматические профили. Сопоставление идёт
по точному имени активного процесса без учёта регистра; пути и команды
запуска не принимаются. Одно имя EXE — один профиль, максимум 50 профилей.

Профиль хранит оформление, компактный режим, масштаб, монитор, автоскрытие,
эффекты и отдельные положения полного/компактного виджета. Без подходящего
профиля восстанавливаются обычные настройки. При открытии самого Liberty Wave
активный профиль сохраняется, чтобы его можно было настроить. Изменения вида
и перемещение записываются в активный профиль, не в обычные настройки.
Удаление/выключение профиля возвращает обычный вид. Бинды и выбранный источник
музыки остаются общими. Профили хранятся в прежнем `widget.json`; старый экспорт
настроек версии 1 переносит только обычные настройки, без профилей.

## Голос при удержании

Назначьте действие «Голос: удерживать для команды» в «Горячие клавиши», затем
включите голосовое управление в «Мой виджет». По умолчанию обе настройки
выключены. Используется локальный `System.Speech` Windows; нужны микрофон,
разрешение Windows на его использование и установленный совместимый SAPI
распознаватель русского или английского языка. Если русского нет, выбирается
английский. При отсутствии распознавателя/микрофона показывается ошибка.

Русские команды: «пауза», «продолжить», «следующий трек», «предыдущий трек»,
«громче», «тише», «выключить звук», «включить звук».
Английские: pause, resume, next track, previous track, volume up, volume down,
mute, unmute. Язык текущего распознавателя показывается во время удержания.

Микрофон открывается на удержании назначенного сочетания и закрывается при
отпускании, отключении функции, записи новых биндов или через 15 секунд.
Нужна новая попытка удержания для следующей команды. Распознавание ограничено
грамматикой команд, порогом уверенности 0.65 и одной командой на удержание.
Смена выбранного музыкального источника отменяет текущую голосовую команду.
Команды проверяются обычными ограничениями возможностей плеера. Запись звука
и отправка аудио/текста в сеть не используются.

## Установщик

Windows CI подтвердил два ограничения: обычный дочерний PowerShell связан
с kill-on-close job родительского Electron, а непосредственно отделённый
PowerShell выходит до начала скрипта. Теперь отделяется Node-хост
(`ELECTRON_RUN_AS_NODE=1` в приложении Electron), который удерживает обычный
PowerShell до окончания установки. Подтверждение проверяет PID хоста, PID
установщика, случайный токен и SHA-256. `unref()` само по себе проблему не решает. Сохранены подтверждение подготовки до выхода приложения,
SHA-256, версия EXE в той же папке, защита от коллизий, откат и очистка кэша.

Новая проверка `scripts/check-installer-survival.cjs` завершает именно Node,
который создал установщик, и проверяет результат после его выхода. Сценарии:
обычная папка, кириллица/пробелы и уже существующий файл нужной версии с
правильной суммой. Проверка запускается также из Windows CI.

Исправление относится к будущей сборке. Уже установленная старая 0.6.3
использует прежний launcher, поэтому её первое обновление нужно выполнить
вручную. Исторический отчёт `UPGRADE_CHECK_061_062.md` оставлен без изменений.

## Выполненные проверки

- `npm test`: 93/93, без пропусков; профили, положения, миграция биндов,
  защита голосовой сессии, обновления, SHA-256 и запуск установщика.
- `npm run test:gui`: реальный виджет Electron и управление музыкой.
- `npm run test:automation` под Xvfb: создание/удаление профиля, проверка
  неверных данных, раздельные настройки, голосовой бинд и сохранение после
  перезапуска, без открытия микрофона.
- `npm run test:startup` под Xvfb: 36 холодных запусков с разными DPI,
  масштабом, компактным режимом и эффектами.
- `npm run test:personalization` под Xvfb: прежние настройки, положения,
  импорт/экспорт, автоскрытие и сохранение.
- `npm run test:update-network` в Electron под Xvfb: редиректы, SHA-256,
  отказ от недоверенного хоста и cookies, отмена частичной загрузки.
- `scripts/check-install-update.ps1` и `scripts/check-installer-handshake.cjs`
  с настоящим PowerShell 7.5.4 в Linux: замена, неверная сумма, коллизии,
  откат и очистка. Проверка блокировки файла пропускается этим скриптом в Linux.
- `scripts/check-installer-survival.cjs` с PowerShell: выход настоящего
  родителя, замена/проверка файлов и очистка во всех трёх сценариях.
- `windows-automation.ps1 -InitializeOnly`: компиляция C# и речевых API;
  `scripts/check-automation-bridge.cjs`: неблокирующее чтение stdin,
  повторная настройка и выключенный микрофон.

Локальные результаты выше получены в Linux. Дополнительно Windows CI
[41624159205](https://github.com/dyushaboldyusha-a11y/music-adapter/actions/runs/41624159205)
прошёл полностью: 93 модульных теста, Windows-интеграции, настоящий PowerShell,
выход родителя установщика, компиляция/протокол голосового моста, сборка EXE,
проверка оформления и весь браузерный набор. Отдельно добавлен тест цепочки
Electron → Electron-as-Node → PowerShell с выходом исходного Electron; локально
он прошёл, Windows повторяет его перед публикацией тега.

Не подтверждены автоматическими проверками:
работа с реальными активными окнами/клавишами Windows и микрофоном, полный переход между Windows EXE с автоматическим перезапуском. В Windows CI
добавлены проверки компиляции/протокола моста и выхода родителя установщика;
CI успешно выполнен для указанного коммита и повторяется для релизного тега.
Полный переход настоящего переносимого EXE и ручная проверка удержания/отпускания
голоса и переключения профилей в игре остаются отдельными проверками.

После отдельного разрешения пользователя ветка отправлена в GitHub. Результаты
локальных проверок выше относятся к восстановлению; статус Windows CI и выпуска
